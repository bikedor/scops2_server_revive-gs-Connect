# SCOPS beta (turn-key)

A complete copy of the SCOPS server with the experimental fixes below, set up to run **on the same VPS as the main
server, from its own folder**, one at a time. Nothing in the main server's folder is changed except when you choose to
copy data back to it. Separate from Sneaky's [SPEARTECH/scops2_server_revive](https://github.com/SPEARTECH/scops2_server_revive).

**Status:** SRP wrap, relay join port, warm holes and the silence log were tested in real sessions (2026-11-11..13). Leave grace, the no-reply move, account check and game check were deployed 2026-11-13 (password change tested on PCSX2). The SRP-session (third joiner) fix and reuse quiet were deployed 2026-11-14. Hold until pinged (hosting with no port forward) is new and only tested in the scenario replay (`tools/sim/relay_scenarios.py`).

## Day to day
| Double-click | What it does |
|---|---|
| **`BETA Server.bat`** | Stops the main server if it runs, sets up Python, offers to copy accounts/friends/ladder from main, starts the beta (same I/L menu as before). Press any key in it to stop the beta; it then offers to copy the data back to main and to start the main server again. |
| `Copy main data to beta.bat` | Accounts, friends, ladder: main -> beta. Only while no server runs. |
| `Copy beta data to main.bat` | The same, beta -> main. |
| `Update beta.bat` | `git pull` of the latest beta from your private GitHub repo. Your data and settings are not touched. |

The first start asks for the main server's folder (for example `C:\scops2_server_revive`) and saves it in
`beta_config.bat`. Delete that file to choose again.

**Data copies** cover everything in `state\` (`users.json`, `friends.json`, `ladder_stats.json`, `motd.txt`,
`ranked_mode.txt`, ...) except the runtime files `lobby_rooms.json` and `relay_map.json`. Before anything is overwritten,
the side being overwritten is backed up to the beta's `state_backups\<date-time>-beta` or `-main`. To undo a copy, copy
that backup folder's files back into `state\`.

**Python:** nothing to install. `pylib\` carries the three modules the server needs (rsa, pyasn1, dnslib). If the main
server has a `.venv`, the beta links to it (a folder junction: no copying) and uses that Python; otherwise it uses the
system `python`. Either way the bundled modules are used, so no `pip install`.

**Main and beta never run together:** they use the same ports (DNS 53, 443, lobby 40000/40005, relay 45000-45012,
10070-10080). The launcher stops the main server fully, including its old launcher window, so closing that old window
later cannot stop the beta.

## Put it on the VPS (once)
Copying folders on the VPS is slow, so use a **private GitHub repo** and let the VPS pull it.

On your PC (this zip already is a git repo with one commit, branch `main`):
1. On github.com create a new **private** repository, for example `scops-beta`, with **no** README or licence (empty).
2. Extract the zip, open a terminal in the `scops-beta` folder:
   ```
   git remote add origin https://github.com/bikedor/scops-beta.git
   git push -u origin main
   ```

On the VPS:
1. Install **Git for Windows** (git-scm.com, defaults are fine).
2. In a terminal, in the folder that should hold the beta (next to the main server is fine, not inside it):
   ```
   git clone https://github.com/bikedor/scops-beta.git
   ```
   The first time, Git opens a GitHub sign-in window (Git Credential Manager); sign in and it remembers you.
   Alternatively, use a fine-grained personal access token with read-only access to just this repo.
3. Double-click `scops-beta\BETA Server.bat`.

After that, changes go: edit on your PC -> `git commit` + `git push` -> on the VPS **`Update beta.bat`** (pulls only
what changed).

No Git on the VPS? Copy the zip once, extract it, and run `BETA Server.bat`; it works the same, only `Update beta.bat`
needs Git.
